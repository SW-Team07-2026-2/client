> - **로그인은 카카오만** — Google 로그인 제거 (25-13 해소).
> - **동의 내역 저장** — 콜백에서 그 사용자의 카카오 토큰으로 `GET /v2/user/service_terms` → 가입 때 `member.user_agreement`(V6 · §1-3)에 `channel = KAKAO_SYNC` 로 복사. 카카오 조회가 실패해도 로그인은 막지 않습니다(빈 목록 · 경고 로그 — 원본은 카카오에 있음). 마케팅 철회(revoke)는 설계 (25-15).

> - **본인인증 폐기** — 인가(계약)도 없고, 결제자 확인은 결제창(PG)이 합니다. Member 본인인증 API · 더미 인증기 · 컬럼(`V7__drop_identity_verification.sql`) · Concert 예매 진입 검사(`VERIFIED`) · 약관 제3조 · 처리방침 행을 지웠습니다. 🔴 1인 1계정은 이제 **카카오 계정 기준**입니다 — 같은 사람이 카카오 계정 두 개로 들어오는 것은 막지 못합니다. 이름이 필요하면 카카오 싱크 `name` 동의 항목(비즈 앱 검수)으로 받습니다 (25-14 해소).
> - **배송지는 가입 때 받지 않습니다** — 첫 굿즈 · 음반 결제 화면에서 입력한 주소를 기본 배송지로 저장합니다 (M20 → `member.shipping_address` · `user_id` → `users.id`). 25-12 해소.
> - 약관 · 정책 화면(§2)과 푸터(§3)는 그대로 — 카카오 싱크 약관 설정에 본문 URL 을 등록합니다.

## 1. 가입 흐름

✏️ 11/05 · ✅ 구현 · 운영 배포 (11/06)

```
[카카오 동의 화면 — 닉네임 · 이메일] ─▶ G2 콜백 (Gateway)
   ① Member I1 /internal/auth/issue { provider, providerUid, email, nickname, profileImageUrl }
        ├─ 기존 회원 → AT · RT · XSRF 쿠키 → 302 홈
        └─ 처음 → users 를 만들지 않음
                 사인업 토큰 (JWT HS256 · signup.token-secret · 30분 · {type:SIGNUP, newUser:true, provider, providerUid, jti})
                 가입 대기 값 Redis auth:signup:{provider}:{providerUid} = {jti, email, nickname, profileImageUrl}
                 → SIGNUP · XSRF 쿠키 → 302 /signup
[/signup ① 약관 동의] M24 GET /api/members/terms (공개) … 체크 결과는 화면에만 (§1-1)
[/signup ② 밴드 고르기] X4 (공개) … 고른 밴드는 화면에만
   ─▶ G13 POST /api/auth/signup { artistIds, agreements: [{ termsId, agreed }] }   ← 「완료」 · 「건너뛰기」(artistIds 빈 배열)
        └─ Member I28: 서명 · 만료 확인 → 약관 검사 (400 · 409 면 여기서 끝 · 토큰은 그대로)
                       → 가입 대기 값을 jti 가 맞을 때만 꺼내며 삭제 (Lua · 1회용)
                       → users + follow(+ member.activity FOLLOW) + user_terms 한 트랜잭션 → AT · RT
```

동의 내용은 사인업 토큰에 넣지 않습니다 — 토큰은 콜백에서 이미 서명돼 나갔고(약관 화면보다 먼저), “누가 가입 중인지”만 증명합니다. 동의는 가입 요청(G13)과 함께 받아 회원 · 팔로우와 같은 트랜잭션에 씁니다.

- 10/28 설계 (카카오 싱크 · 폐기)
    
    ```
    [카카오 동의 화면 — 카카오 싱크] ─▶ G2 콜백 (Gateway)
       ① 카카오 GET /v2/user/service_terms (그 사용자의 카카오 토큰 · 요청이 끝나면 버림)
       ② Member I1 /internal/auth/issue { provider, providerUid, …, agreements }
            ├─ 기존 회원 → AT · RT · XSRF 쿠키 → 302 홈 (지금과 같음)
            └─ 처음 → users 를 만들지 않음
                     사인업 토큰 (JWT HS256 · signup.token-secret · 30분 · {type:SIGNUP, newUser:true, provider, providerUid, jti})
                     가입 대기 값 Redis auth:signup:{provider}:{providerUid} = {jti, email, nickname, profileImageUrl, agreements}
                     → SIGNUP · XSRF 쿠키 → 302 /signup
    [밴드 고르기] X4 (공개) … 고른 밴드는 화면에만
       ─▶ G13 POST /api/auth/signup { artistIds }   ← 「완료」 · 「건너뛰기」(빈 배열)
            └─ Member I28: 서명 · 만료 확인 → 가입 대기 값을 jti 가 맞을 때만 꺼내며 삭제 (Lua · 1회용)
                           → users + follow(+ member.activity FOLLOW) + user_agreement 한 트랜잭션 → AT · RT
    ```
    

프론트는 사인업 토큰을 읽을 수 없습니다(HttpOnly). 처음인지는 302 목적지(`/signup`)로 알고, 토큰이 없거나 만료면 G13 이 401 `SIGNUP_EXPIRED` 를 줍니다.

- 10/27 설계 (약관 동의 화면 · 10분 티켓)
    
    ```
    [카카오 · Google] ─▶ G2 콜백 ─▶ Member I1 → 처음이면 가입 티켓 (Redis member:signup:{ticket} · 10분) → 302 /signup/terms
    [약관 동의 화면] ─▶ G13 POST /api/auth/signup { agreements } → I28 → users + user_agreement → 장르 → 밴드
    ```
    

**콜백에서 회원을 먼저 만들고 약관을 나중에 받지 않는 이유** — 그러면 “약관에 동의하지 않은 회원”이 생깁니다. 약관 화면에서 나가 버리면 지울 대상이 남고, 그 회원이 다른 화면으로 들어오는 것도 막아야 합니다. 티켓 방식이면 중간에 나갔을 때 **DB 에 아무것도 남지 않고** Redis 티켓도 10분 뒤 사라집니다.

**약관을 취향 고르기보다 앞에 두는 이유** — 고른 장르 · 팔로우한 밴드는 개인정보(처리방침 1항)라 동의 전에는 저장할 수 없습니다. ✏️ 10/28 카카오 싱크라 동의는 콜백 전에 끝나고, 팔로우는 가입(G13)과 같은 트랜잭션에서 저장합니다.

**✏️ 10/28 사인업 토큰을 JWT 로 · 가입 대기 값을 Redis 에 둔 이유** — 토큰만 보고 위조 · 만료를 걸러 Redis 조회 전에 끊습니다. 다만 JWT 는 누구나 디코드하므로 이메일 · 닉네임 · 동의 내역은 넣지 않고 Redis 에 둡니다(AT 와 같은 원칙). 키를 사람 기준(`provider:providerUid`)으로 잡아 다시 로그인하면 이전 토큰이 무효가 되고, jti 비교 + 삭제를 Lua 하나로 해서 「가입하기」를 두 번 눌러도 한 번만 성공합니다. 탭 두 개로 각각 가입하면 두 번째는 먼저 만든 회원으로 로그인합니다(팔로우 · 동의 이력은 다시 쓰지 않음).

**✏️ 10/28 배송지** — 가입 단계에서 받지 않고 첫 굿즈 · 음반 결제 화면에서 받습니다 (주소 검색은 [23](23_프론트_API_목록.md) §2-2 카카오 우편번호 서비스). 처리방침 · 수집 표에 배송지(받는 분 이름 · 연락처 · 주소) 행을, 위탁에 택배사를 추가했습니다(데모 약관 v0.1 · 업체는 【확인 필요】).

### 1-1. 약관 동의 화면 — ✏️ 11/05 되살림 (`/signup` ① · 10/28 폐기 → 카카오 싱크 폐기로 다시 우리 화면)

행은 **M24 응답 `items` 순서 그대로** 그립니다 (화면에 문구 · 개수를 박지 않음 — 약관이 바뀌면 서버만 바꿈). 지금 v1 은 아래 4줄입니다.

| 행 | 문구 (= `title`) | 구분 (= `required`) | 「보기」 (= `content` 마크다운) |
| --- | --- | --- | --- |
| 전체 동의 | 전체 동의 (선택 항목 포함) | — | — |
| AGE14 | 만 14세 이상입니다 | **[필수]** | 짧은 안내 (펼치지 않아도 됨) |
| TOS | 이용약관 동의 | **[필수]** | 제1~7조 · 부칙 |
| PRIVACY | 개인정보 수집 및 이용 동의 | **[필수]** | 수집 항목 · 목적 · 보유 기간 · 거부할 권리(거부하면 가입 불가) |
| MARKETING | 마케팅 정보 수신 동의 | [선택] | 이용 항목 · 목적(이메일 · 서비스 내 알림) · 보유 기간 · 철회 방법 |
- 필수를 다 체크해야 「다음」(→ ② 밴드 고르기)이 열립니다. 서버도 G13 에서 다시 검사합니다 (400 `REQUIRED_AGREEMENT_MISSING`).
- 「전체 동의」는 선택 항목까지 체크합니다. 항목 하나를 끄면 「전체 동의」도 꺼집니다.
- 「보기」는 **그 자리에서 펼칩니다** (아코디언 · 모달). 다른 화면으로 보내면 체크한 내용이 사라집니다.
- 체크 결과는 메모리에만 두고 G13 에 `agreements: [{ termsId, agreed }]` 로 한 번에 보냅니다 — 약관 화면에서 서버를 부르지 않습니다. `termsId` 는 M24 값 그대로.
- 「가입 그만두기」는 로그인 화면으로 돌아갑니다. 사인업 토큰은 지우지 않고 30분 뒤 만료에 맡깁니다.
- 화면에는 이메일을 보이지 않습니다 (가입 대기 값은 서버 Redis 에만).
- 화면 상세 · 코드 예시는 [31](31_프론트_연동_플로우.md) §4-2, 요청 · 에러는 [26](26_프론트_API_명세서.md) §1 G13 · §2-6.
