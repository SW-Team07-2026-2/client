# v2 프론트 체크사항

> **기준일: 2026-11-13.** 운영 `https://api.indig.co.kr`의 백엔드가 **v2로 바뀌었습니다**(member · catalog · concert · payment · gateway). API 전체는 [v2_API_명세서](v2_API_명세서.md)에 있습니다.
이 문서에는 프론트(`frontend/` · 사용자 화면과 관리자 화면)가 **확인하거나 바꿔야 할 것**만 모았습니다. 프론트 코드는 백엔드 담당이 고치지 않았습니다(읽기만 함).
표시: 🔴 지금 운영에서 깨지는 것 · 🟡 화면을 붙일 때 v1과 다른 것 · ⚪ 참고
> 

## 0. 운영에서 바뀐 것 (11/13)

| 항목 | 내용 |
| --- | --- |
| DB | member · catalog · concert · payment 스키마를 비우고 다시 만들었습니다. **회원은 1명(id 1, 카카오)만 남겼습니다.** 프론트 담당자 계정으로 보여 지우지 않았습니다 |
| 데이터 | 아티스트 · 앨범 · 상품 · 공연장 · 공연이 **0건**입니다. 목록 API는 200 + 빈 목록입니다 |
| 로그인 | 남겨 둔 계정도 예전 토큰이 무효일 수 있습니다. 401이 나오면 카카오 로그인을 다시 하면 됩니다 |
| 챗봇 | 11/13 운영 배포 그대로입니다. Gateway에서 챗봇에 없는 경로 두 개를 지웠습니다(4장) |
| 관리자(Studio) | main에만 있고 **배포하지 않았습니다**(KT Cloud 대기). 관리자 화면은 아직 운영에서 붙일 수 없습니다 |

## 1. 🔴 지금 운영에서 깨지는 것

### 1-1. 새 회원 가입이 400으로 실패합니다

- 가입 완료 `POST /api/auth/signup`은 **`artistIds`가 1개 이상이어야 합니다**(11/08부터). 빈 배열이면 400 `INVALID_REQUEST`입니다.
- 지금 코드에서 빈 배열이 나가는 곳:
    - `src/routes/welcome/+page.svelte` `handleSkip()` — 「건너뛰기」가 `submitSignup([])`을 보냅니다.
    - 같은 파일 `handleComplete()` — `selectedIds`를 `parseInt`로 숫자로 바꾸는데, `FdWelcomeDisplay.svelte`의 목록이 `id: 'illit'` · `'buzz'` 같은 **글자 id**(고정 예시 데이터)라 전부 `NaN`으로 걸러져 빈 배열이 됩니다.
- 결과: 운영에서 새 카카오 계정은 가입을 끝낼 수 없습니다(화면에는 “가입에 실패했어요” 알림).
- 고칠 것:
    1. 밴드 고르기 목록을 **`GET /api/catalog/artists`**(공개 · 페이지 형식)에서 받고 숫자 `id`를 보냅니다.
    2. 「건너뛰기」를 없애거나, 최소 1개를 고르게 막습니다(또는 백엔드와 규칙을 다시 정합니다).
- ⚠️ **지금 Catalog에 아티스트가 0명입니다.** 1번으로 바꿔도 목록이 비어 가입을 끝낼 수 없습니다. 수집기 · 시연 데이터가 들어오기 전까지는 운영에서 새 가입을 시험할 수 없습니다([v2_후속_작업](v2_후속_작업.md) 2장 · 5장 ①).

### 1-2. 챗봇 주소가 로컬입니다

- `src/lib/ai/chatStream.ts`의 `DEFAULT_CHAT_API_URL = 'http://localhost:8000/chat'`, `src/lib/config/setting.ts`의 `CHAT_AI_API_URL = "http://localhost:8000"`이고 `BotArea.svelte`가 이 기본값을 씁니다.
- 운영 주소: **`${API_URL}/api/chatbot/chat`**(기록 조회 · 질문), 업로드는 `/api/chatbot/chat/upload`.
- 같이 바꿀 것:
    - 질문 · 업로드 POST에 **`X-XSRF-TOKEN`** 헤더(`auth.xsrfToken`). 없으면 403 `CSRF_*`. 지금은 `Authorization: Bearer`만 붙입니다(운영은 쿠키 인증이라 `credentials: 'include'`만 있으면 됩니다).
    - 업로드는 **1 MiB까지**(Gateway가 413). 챗봇 문서의 20MB 안내를 고치고, 올리기 전에 크기를 확인합니다.
    - 오류 모양 두 가지: Gateway가 막은 것은 `{ isSuccess, code, message }`, 챗봇이 낸 것은 `{ detail }`.
    - 호출 한도 분당 5회(429), 응답 30초를 넘으면 스트림이 끊길 수 있습니다.

## 2. 🟡 화면을 붙일 때 v1과 다른 것

지금 `concert` · `goods` · `album` · `artist` · `mypage` 화면은 백엔드를 부르지 않습니다. 붙일 때 아래를 v2 기준으로 맞춥니다.

### 2-1. 공통

| 항목 | v2 |
| --- | --- |
| 목록 형식 | 카탈로그 · 공연은 **페이지**(`?page=&size=` → `{ items, page, size, hasNext }`), 회원 · 주문 · 예매 · 결제는 **커서**(`?cursor=&size=` → `{ items, nextCursor, hasNext }`) |
| enum 파라미터 | 목록 밖 값은 400입니다. 값 목록은 명세서 12장. **한글 표기(라벨)는 프론트가 정합니다** |
| 장르 | catalog · concert 공통 **23개**(`INDIE_ROCK` · `SHOEGAZE` · `CITY_POP` …). `K-POP` · `ROCK` · `POP` · `BALLAD`는 없습니다. `FdWelcomeDisplay.svelte`의 `genre: 'K-POP'` 같은 예시 값도 바꿔야 합니다 |
| 이미지 | `thumbnailUrl` · `profileUrl` · `posterUrl` · `imageUrls`는 URL 문자열입니다(수집기가 S3에 올린 주소 · 11/13 결정). 비어 있을 수 있으니 기본 이미지를 둡니다 |
| CSRF | 상태를 바꾸는 요청 전부 `X-XSRF-TOKEN` |
| 취소 · 탈퇴 · 로그아웃 | 누르면 **확인 모달**을 먼저 띄웁니다. 시간이 끝난 경우(선점 만료 등)는 확인이 아니라 **알림 창**입니다 |

### 2-2. 회원 (member)

| v1 | v2 | 할 것 |
| --- | --- | --- |
| 피드 `GET /api/members/feed` | **삭제** | 팔로잉 소식은 알림 목록에서 |
| 위시리스트 `/api/members/wishlist/**` | **삭제** | 장바구니 `/api/cart/**`(2-3) |
| 알림 목록 | 나의 알림 + 아티스트 소식이 **한 목록**(최신순) · `{ id, type, target, targetId, artistId, message, isRead, createdAt }` | `target`으로 이동 화면을 고릅니다(명세서 2-4). 누르면 `POST /api/members/notifications/{id}/read`, 404면 목록에서 지우기 |
| 안 읽은 수 | `GET /api/members/notifications/badge` → `{ count }` |  |
| 보유 음반 | `{ physicalAlbumId, optionId, acquiredAt? }` — **옵션 필수** · 삭제 `DELETE /api/members/collections/{id}` | 응답에 이름 · 이미지가 없어서 `GET /api/catalog/products?ids=`로 채웁니다 |
| 내 정보 | `wishlistCount` 없음 · `followCount` · `collectionCount` |  |
| 회원 탈퇴 | `DELETE /api/members/me` — **즉시 전부 삭제** | 확인 모달(“결제 대기 중인 주문 · 예매는 취소됩니다”) → 성공하면 Gateway가 쿠키를 지우므로 로그아웃 화면으로, 메모리의 CSRF 토큰도 버립니다 |
| 행동 메트릭 | `POST /api/members/me/metrics` `{ events: [...] }` | 로그인 상태에서만. `metricId`는 이벤트마다 UUIDv7. **버퍼에 모아** 20개 · 10초 · 페이지 숨김 때 보냄. 떠날 때는 `fetch(…, { keepalive: true })` + `X-XSRF-TOKEN`(`sendBeacon`은 헤더를 못 붙여 403). 실패 · 429는 같은 `metricId`로 다시(버퍼 최대 200) |
| 닉네임 | 2~10자 · 응답 `{ userId, nickname }` |  |

### 2-3. 카탈로그 · 장바구니 · 주문 (catalog)

| 항목 | v2 | 할 것 |
| --- | --- | --- |
| 판매 단위 | **옵션**(`optionId`) — LP 블랙 · 컬러, CD · 카세트 “기본”, 굿즈 사이즈 | 상품 상세의 `options[]`에서 고르게 합니다. `soldOut`이면 막습니다 |
| `lps` 등 | 피지컬 앨범은 `GET /api/catalog/physical-albums`(`format` LP · CD · CASSETTE) |  |
| 장바구니 | `GET /api/cart` · `PUT /api/cart/items/{optionId} { qty }` · `DELETE …/{optionId}` · `DELETE /api/cart` — **조회도 로그인** | 수량은 “더하기”가 아니라 “이 값으로”. 옵션 20가지 · 옵션당 10개(409 `CART_FULL`) |
| 주문 | `POST /api/catalog/orders { items: [{ optionId, qty }], shipping }` → `pgOrderId` · `amount` | 토스 결제창 → **`POST /api/payments/confirm { paymentKey, orderId: pgOrderId, amount }`** |
| 주문 취소 | 결제 뒤 취소는 상태가 `REFUNDED` | 상태 라벨에 `REFUNDED` 추가 |

### 2-4. 공연 · 예매 (concert)

| 항목 | v2 | 할 것 |
| --- | --- | --- |
| 🔴 장르 필터 | `GET /api/concerts?genre=` — 23개만 | 목록 밖 값(`ROCK` 등)은 400 |
| 공연 상세 새 필드 | `description` · `terms` · `requirements` · `posterUrl` · `imageUrls[]` | 상세 · 약관 · 요구사항 · 포스터 · 이미지 영역. 없으면 `null` · 빈 배열 |
| 타이머 | 대기열 입장부터 결제하기까지 **7분 하나**. 좌석 응답의 `expiresIn`(남은 초)으로 | 끝나면 알림 창 → 대기열로 |
| 대기열 | `QueueStatus.state` = `WAITING` · `ADMITTED` · `EXPIRED`, `pollAfterMs`마다 조회 | `ADMITTED`의 `entryToken`을 좌석 · 예매 요청에 `X-Entry-Token`으로 |
| 좌석 선점 | `POST /api/concerts/{id}/bookings { seatIds }` — **금액은 서버가 정함** | 409 `SEAT_TAKEN`(+`seatId`) · `HOLD_EXISTS`(+`bookingId` → 먼저 취소) |
| 🔴 티켓 결제 승인 | **`POST /api/concerts/bookings/{id}/confirm { paymentKey, amount }`**(결제 서비스 confirm 아님) | 503 **`PAYMENT_PENDING`**은 실패가 아닙니다 — “결제 확인 중” 화면에서 예매 상세를 다시 조회합니다. 410 `HOLD_EXPIRED`는 돈이 나가지 않은 만료 |
| 입장 QR | `GET /api/concerts/bookings/{id}/entry-qr` — 30초 유효 | 20초마다 다시 부릅니다 |

### 2-5. 결제 (payment)

- 결제 내역 `GET /api/payments/me`(커서). 티켓 결제 취소는 결제 API가 아니라 **예매 취소**(`POST /api/concerts/bookings/{id}/cancel`)로 합니다(결제 API로 부르면 409 `USE_BOOKING_CANCEL`).
- 토스 **테스트** 키입니다. 카드 · 토스페이만 됩니다(카카오페이 · 페이코 안 됨, 가상계좌 거절).

## 3. 관리자 화면 (`src/lib/admin` · Studio)

> Studio는 **배포 전**입니다(KT Cloud 대기). 아래는 배포되면 붙일 때의 규칙입니다. 상세: studio-service `docs/v2_studio_service_re.md` 11장 · 명세서 8-1.
지금 `src/lib/admin/api.ts`는 비어 있습니다(주석 한 줄).
> 

| 항목 | 규칙 |
| --- | --- |
| 주소 | Studio 직접(Gateway 아님). 주소는 배포 때 정합니다 |
| 쿠키 | 모든 요청 `credentials: 'include'`. 관리자 화면이 다른 사이트(예: Vercel)에 있으면 Studio가 `SameSite=None`으로 바꿔야 합니다 → 화면 주소를 백엔드에 알려 주세요 |
| 로그인 | 두 화면: 아이디 · 비밀번호 → `next`가 `OTP_ENROLL`이면 `otpauthUri`로 **QR** + `secret`(직접 입력용) → 6자리 코드 |
| 탭 | `GET /api/studio/me`의 **`menus`에 있는 탭만** 그립니다. 탭 이름을 코드에 고정해 두고 역할로 숨기지 않습니다(다른 역할의 탭이 번들에 남음) |
| 역할 6개 | `MASTER`(전부 + 관리자 계정 · 작업 기록) · `STAGE`(무대) · `CONCERT`(공연) · `GOODS`(굿즈 · 피지컬) · `CS` · **`CHECKER`(검표 · 11/13 신규)** |
| CSRF | POST · PUT · PATCH · DELETE에 **`X-CSRF-Token: <me.csrfToken>`**(사용자 화면의 `X-XSRF-TOKEN`과 이름이 다릅니다) |
| 401 · 404 | 401 `UNAUTHENTICATED` → 로그인 화면. 404는 “없는 페이지”로만(권한 안내 문구 금지 — 권한 밖도 404) |
| 502 · 503 | 연결된 서비스 문제입니다. 로그아웃시키지 않습니다 |
| 무대 그리기 | 검증 요청 뒤 2~3초마다 작업을 조회 → `REVIEW`면 `…/image`와 `values`를 보여 주고 확인. `FAILED`면 `errorMessage` + 다시 요청 |
| 공연 등록 | 포스터 · 이미지는 **URL 입력**입니다(업로드 없음 · 11/13 결정: 크롤링 이미지는 수집기가 S3에 올림). 단독 공연은 장르를 보내지 않습니다. 라인업은 Catalog 아티스트에서 고릅니다 |
| CS | 회원 목록의 이메일은 가려져 옵니다(`ab***@…`), 상세는 전체. 취소 대행은 **확인 모달** |
| 검표 | 카메라로 QR을 읽어 `token`만 보냅니다(검표자는 서버가 채움). 409 `ALREADY_CHECKED_IN`이면 응답의 `checkedInAt`(먼저 입장한 시각)을 보여 줍니다 |

## 5. 프론트 담당자에게 확인받을 것

1. 1-1의 「건너뛰기」를 없앨지, 백엔드가 “아티스트 0개 가입”을 다시 허용할지.
2. 관리자 화면을 어느 주소에 둘지(쿠키 `SameSite`가 달라집니다).
3. 남겨 둔 회원 id 1이 프론트 담당자 계정이 맞는지. 아니면 알려 주세요(지금은 지우지 않았습니다).
